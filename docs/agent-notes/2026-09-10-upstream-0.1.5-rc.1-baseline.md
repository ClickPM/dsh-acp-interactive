# Upstream 0.1.5-rc.1 Baseline

The composed Harness baseline moves from `0.1.2-rc.1` to `0.1.5-rc.1`. The advertised ACP surface does not move with it: `@agentclientprotocol/sdk` stays at `1.4.0`, which is also what the official `@deepseek-ai/dsh-acp` pins, and the official package publishes the same twelve spec files, with the one aligned spec (`codec.spec.ts`) byte-identical. This is a runtime migration, not a protocol change, and the decisions below are about keeping the same ACP behavior true on the new runtime.

Everything here was measured before it was changed: a clean copy of the repository with every `@deepseek-ai/dsh-*` dependency at `^0.1.5-rc.1`, typechecked, built, run against the suite, and driven as a real launcher over stdio.

## Live streaming moves from durable chunks to process-local frames

Session format `0.1.5-rc.1` writes is v3 (the `0.1.2-rc.1` writer was v0). The v2 step embedded each model attempt's provider stream inside one durable settlement — `assistant/message` for a surface result, or a log-only `assistant/attempt` for a failed, retried, cancelled, or stream-error attempt — and deleted the per-token `assistant/chunk` event. That event was this server's only source of `agent_message_chunk` and `agent_thought_chunk`, and it was the only event type this server projects that vanished.

The replacement is the agent-scoped `agent/assistant-stream` event: a `start` frame naming the attempt's turn and step, transient `chunk` frames carrying only the attempt id, and an `end` frame. The loop appends the durable settlement before it publishes a committed `end`, so the frames are presentation data and the settlement stays the replay source. Three consequences were decided rather than inherited:

- The bridge keeps one live attempt per session, captured from the `start` frame, because a chunk frame does not name its turn or step. The ACP `messageId` is still derived as `<session>:assistant:<turn>:<step>`, so a message streamed live and the same message replayed by `session/load` keep the same id, which `tests/schema-conformance.spec.ts` pins. A chunk before its start, after its end, or from a different attempt id is dropped.
- `assistant/attempt` is explicitly not projected. It is evidence for diagnostics and accounting, not model-visible surface; projecting it would show a failed attempt to the editor as an agent message. `assistant/message` continues to project only its `usage`, because its text already streamed.
- Every attempt streams, including a retried one. ACP has no primitive to retract chunks already delivered, so a retry appends to the same message after the failed prefix. This is exactly what the former projection of every durable `assistant/chunk` did; the alternative — stream nothing until settlement — would have removed incremental output from the editor to avoid a rare duplicate.

The architectural invariant in `AGENTS.md` holds unchanged: model-visible content is durable in the session log before request assembly, and UI-only ACP updates never enter model context. The live frames are UI-only by construction.

## Two silent breaks and two loud ones

`@deepseek-ai/dsh-system-prompt` renamed its `persona` config to `personaPrefix` and added a `personaSuffix` rendered after first-party guidance. Schemastery keeps an unknown key and ignores it, so the old `config/cordis.yml` row would have mounted without an error and simply lost the persona. Every row of the profile that carries a `config` was checked against the `0.1.5-rc.1` schema; this was the only unknown key. The whole persona line stays in `personaPrefix` because the former `persona` was order-0, so the rendered prompt order is unchanged. Upstream's own `acp-app` bundle splits the working-directory sentence into `personaSuffix`; adopting that split would change section order and is a separate review.

`check:profile` had been crashing since `1.1.0`: its reference file `apps/cli/config/agent-presets/standard/agent.cordis.yml` moved to `packages/preset/agent-presets/presets/standard/agent.cordis.yml` before `0.1.2-rc.1`, so the audit never ran against that baseline. With the path corrected it reports real drift, recorded in the manifest snapshot: the official standard preset now composes `@deepseek-ai/dsh-web-fetch-http` (this profile already did) and no longer composes `@deepseek-ai/dsh-tool-subagent-report` (this profile never did). Neither changes the shipped composition.

The loud ones: `ctx.accessor('agent')` is gone and `AgentSetup` receives the unpublished agent as its second argument, which made `session/new` fail with `cannot get property "agent" without inject`; and `SessionPersistence` was rewritten around per-session handles (`create`/`open` return a `SessionHandle`, plus `flush`/`stat`/`list`), which only this repository's in-memory test double implements — `src/` reads sessions through `ctx.sessionQuery`.

That test double now also owns live routing. A published backend subscribes to `session/event`, `session/flush`, and `session/disposed` and routes announced events into the one active write handle it holds per session id; the loop only owns the handle. The former fixture received appends from a coordinator that no longer exists, so without routing every created session persisted an empty log. One test expectation changed as a result: a session created through `session/new` and closed is now listed by `session/list`, as it is with the JSONL backend, where the earlier fixture had listed only its hand-seeded rows.

## Persisted sessions migrate on read, sideways

A session written by `1.1.0` is format v0. `dsh-session-persistence-jsonl` now depends on `dsh-session-format-catalog` and the adjacent v0→v1→v2→v3 edges, all transitive, so nothing is added to `config/cordis.yml`. Verified with a real v0 session written by the published `1.1.0` launcher and read by the `0.1.5-rc.1` build: `session/list` and `session/load` succeed, and the migration publishes a sibling `session.v3.jsonl.zstd` while leaving the v0 file byte-intact. Old sessions therefore survive the upgrade, occupy roughly twice their previous space on first read, and a rollback to `1.1.0` keeps reading the v0 file — losing only what was written after the upgrade.

## What the raw failure count hid

A bare dependency bump failed 72 of 139 tests. Sixty-seven of those were one line: the agent-loop testkit now mounts `SessionProjectionRegistry` itself, and `tests/harness.ts` mounted it a second time. After that line, the persona rename, and the setup signature, fifteen remained — about five for streaming and ten for the persistence double — which is the actual size of this move.

## Not adopted, deliberately

Twenty-three packages are new upstream; none is composed here. The `dsh-client-*`, `dsh-api-workspace-files`, `dsh-client-file-upload`, `dsh-client-resources`, `dsh-host-open-in-app`, and `dsh-http-proxy` packages are DeepSeek's own web and desktop client surface with no ACP counterpart. The five `dsh-experimental-agent-team*` packages have no ACP concept to map onto and are marked experimental upstream. `dsh-tool-present` is composable — it injects only `tools`, `fs`, and `sessionProjections` — and would project as a `tool_call` with `locations`, but its value is opening deliverables in the host's default application through `dsh-host-open-in-app`, which ACP has no request for; it stays deferred rather than half-adopted. The `dsh-session-format*`, `dsh-package-manifest`, and `dsh-chunked-list` packages are build-time or transitive.

The new `deepseek-flash` model id is not added to the `llm-deepseek` row; the three pinned ids all survive. The launcher-resolved bundle patch layer remains unadopted for the reasons recorded in the `0.1.2-rc.1` note.
