# Upstream 0.2.0-rc.1 Baseline

The composed Harness baseline moves from `0.1.5-rc.3` to `0.2.0-rc.1`. The advertised ACP surface remains on `@agentclientprotocol/sdk` `1.4.0`. Upstream 0.2.0-rc.1 brings major runtime architecture upgrades across message representations, configuration, shell execution, and MCP transport.

## First-Class ToolResultMessage

In 0.1.5, tool results were wrapped inside user-role messages as a `tool-result` content block (`content: [{ type: 'tool-result', toolCallId, isError, content }]`).

In 0.2.0-rc.1:
- `ToolResultBlock` is removed from the content block union.
- Tool results become a distinct top-level message role `role: 'tool'` represented by `ToolResultMessage`.
- `toolCallId` and `isError` are top-level properties on `event.data.message`, whose `content` directly contains the result content blocks.
- Adapted `src/index.ts` (`projectEvent`, `validateReplayableHistory`) and `src/subagents.ts` (`childEvent`) to project from `ToolResultMessage` directly.

## Settings System & Profile-Owned Configuration

Upstream eliminated global `settings.yaml` and deleted `@deepseek-ai/dsh-settings-file`. Instead:
- Plugins declare configurable values directly in their Cordis `Config` schemas.
- Persistent configuration is stored in the profile's `cordis.patch.yml` or the home-level `$DSH_HOME/cordis.patch.yml`.
- The standalone launcher (`src/bin.ts` / `src/setup.ts`) now provides `loadUserPatches` to load `$DSH_HOME/cordis.patch.yml` and cleanly fallback-import legacy `$DSH_HOME/settings.yaml` into patch options passed to `boot()`.
- Official DeepSeek API key discovery was split into `@deepseek-ai/dsh-llm-deepseek-api-key`, which replaces `@deepseek-ai/dsh-llm-deepseek` as the Cordis plugin row in `config/cordis.yml`.

## Shell Convergence on `execute()`

- Upstream deprecated and removed `ctx.shell.run()`, converging all executions on `ctx.shell.execute(spec)`.
- Timed-out commands can now be promoted to background jobs (`kind: 'promoted'`).
- Adapted shell tests in `tests/platform-shell.spec.ts`.

## MCP Client SDK Migration

- `@deepseek-ai/dsh-mcp-client@0.2.0-rc.1` migrated from `@modelcontextprotocol/sdk` to `@modelcontextprotocol/client`.
- The new client uses version negotiation mode `auto` by default, probing servers with `server/discover` before falling back to `initialize`.
- Adapted tests and packed-install verification (`scripts/verify-packed-install.mjs`) to resolve `@modelcontextprotocol/client` and acknowledge `server/discover`.

## Editor Profile & Baseline Reconciliation

- Upstream moved declarative preset definitions from `packages/preset/agent-presets/presets/standard/agent.cordis.yml` to `packages/bundle/web-app/presets/standard.patch.yml`.
- Upstream replaced `@deepseek-ai/dsh-workflow-worker-thread` with `@deepseek-ai/dsh-workflow-ptc`.
- `config/editor-profile.json` and `config/upstream-baseline.json` updated and verified against `dsh-v0.2.0-rc.1`.
- The aligned specification `codec.spec.ts` passes against `src/codec.ts`.
