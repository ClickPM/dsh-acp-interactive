# Upstream 0.2.0-rc.2 Baseline

The composed Harness baseline moves from `0.2.0-rc.1` to `0.2.0-rc.2`. The advertised ACP surface remains on `@agentclientprotocol/sdk` `1.4.0`, and no runtime adaptation was required: this is a patch-level prerelease of the same 0.2.0 line, published about twenty-one hours after `rc.1`.

## What upstream changed

The release is dominated by surfaces this composition does not mount: the web client (long-session rendering and whale animation cost, sidebar workspace open, settings copy), the desktop packaging and CLI registration flow, and the Windows ACL diagnosis skill — the last of which matches the skill this session catalog still carries.

Against the packages this profile composes, the reviewed diff is narrow:

- **`packages/acp/acp`** — only its own `package.json` version changed. The twelve official spec files under `packages/acp/acp/tests` are byte-identical to `rc.1`, so every classification in `config/upstream-baseline.json`, including the single aligned `codec.spec.ts`, still holds verbatim.
- **`packages/session`** — no new format package. The migration chain still ends at `session-format-v3-to-v4`, so sessions written under `rc.1` keep replaying under the same format version.
- **`packages/bundle`** — version bumps only; the preset patch files `check:profile` audits are unchanged.
- **`packages/app/app-boot`** — no changes, so patch-layer loading (`cordis.patch.yml`, legacy `settings.yaml` fallback) behaves exactly as reviewed for `rc.1`.
- **`packages/llm`** — version bumps plus `llm-pi-ai` work in `src/catalog.ts` and `src/replay.ts` with their suites. This is the one behavioral area the composition mounts directly: `llm-pi-ai` backs every non-DeepSeek route in `$DSH_HOME/cordis.patch.yml`, so its catalog/replay changes are what the profile actually exercises.
- **`packages/mcp/mcp-client`** — version bump only.

## Why the pin moved

`package.json` declares `^0.2.0-rc.1`, so any fresh install already resolved `rc.2` silently: `rc.1` was published 2026-09-28 12:18 and `rc.2` on 2026-09-29 09:40, while this repository's lockfile was generated at 09:24 — twenty minutes before `rc.2` existed. Leaving the range as it was meant the locked (tested) tree and the installed (shipped) tree could differ, with the compatibility gate reporting on the older one. The baseline is therefore moved deliberately rather than left to the resolver.

Moving it required a clean resolution: every `0.2.0-rc.2` package pins its siblings with exact `peerDependencies`, so an incremental `npm install` over the `rc.1` tree fails with `ERESOLVE`. `package-lock.json` and `node_modules` were removed and the tree reinstalled, which also updated `@deepseek-ai/cordis` (4.0.4) and `@deepseek-ai/schemastery` (3.18.4) — both unchanged from `rc.1`.
