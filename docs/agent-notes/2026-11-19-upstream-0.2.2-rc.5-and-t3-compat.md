# Upstream 0.2.2-rc.5 Baseline and T3 Code Compatibility

Release `1.5.0` moves the composed DeepSeek Harness baseline from `0.2.0-rc.2` to `0.2.2-rc.5` (pinned ref `dsh-v0.2.2-rc.5`) and resolves four ACP client integration issues surfaced with T3 Code (`driver: "acpRegistry"`). The advertised ACP surface remains grounded in `@agentclientprotocol/sdk` `1.4.0`, with `@deepseek-ai/cordis` `4.1.0`, `@deepseek-ai/schemastery` `3.19.0`, `cordis-plugin-{group,include,loader}` `1.1.0`, `cordis-plugin-timer` `1.2.0`, and `@modelcontextprotocol/client` `2.2.0` (inside `@deepseek-ai/dsh-mcp-client`).

## Upstream 0.2.2-rc.5 Migration

### Composition and Schema Alignment (`config/cordis.yml`, `config/editor-profile.json`)

- **Removal of `dsh-invariants`**: Upstream deleted `@deepseek-ai/dsh-invariants` and all `*/invariant` companion entrypoints (`session-invariant`, `agent-invariant`, `scope-invariant`, `agent-loop-invariant`). Removed those rows from `config/cordis.yml`, deleted `src/invariant.ts`, dropped it from `tsdown.config.ts` and `package.json` `exports`, and removed the package from `package.json` dependencies.
- **Explicit working-directory service (`@deepseek-ai/dsh-working-directory`)**: Added `working-directory` (`inject: ['fs', 'sessionProjections', 'systemPrompt']`) to `config/cordis.yml`, which owns the durable `working-directory:current` runtime-context snapshot. Upstream removed the `{{cwd}}` prompt variable from `agent-loop`, and `dsh-system-prompt` throws on unknown `{{variable}}` references, so `Your working directory is {{cwd}}.` was removed from `system-prompt` `personaPrefix`.
- **Explicit native tool executor (`@deepseek-ai/dsh-tool-executor-native`)**: `dsh-tools` no longer mounts a built-in default executor, so `tool-executor-native` (`inject: ['tools']`) is explicitly composed in `config/cordis.yml` and recorded under `generic-tool-projection` in `config/editor-profile.json`.
- **Session title headroom**: `@deepseek-ai/dsh-session-title` now injects `['sessions', 'sessionProjections', 'agents']`, and `session-title-provider` (`@deepseek-ai/dsh-session-title-first-prompt-llm`) in `config/cordis.yml` raises `maxOutputTokens` from `32` to `4096` (with `timeoutMs: 60000`) so reasoning-capable models do not exhaust the output ceiling before emitting the title text.
- **DeepSeek official model catalog**: Dropped the stale hardcoded `models:` override on `llm-deepseek` in `config/cordis.yml` so `@deepseek-ai/dsh-llm-deepseek-api-key` uses upstream `DEFAULT_MODELS` (`deepseek-flash` with `inputModalities: ['text', 'image']` and `deepseek-v4-pro` text-only) plus live `/models` listing configuration (`DEFAULT_MODELS_TIMEOUT_MS = 5000`, `DEFAULT_MODELS_MAX_AGE_MS = 600000`).
- **Curated profile and deferred `0.2.2-rc.5` candidates**: `npm run check:profile` now audits `61` composed bare plugins across `7` reviewed capabilities in `config/editor-profile.json`. Deleted upstream entries (`@deepseek-ai/dsh-subagent-in-process-driver`, `@deepseek-ai/dsh-tool-ralph`, and the merged `@deepseek-ai/dsh-tool-subagent-control/list-agents` subpath) were removed. New `0.2.2-rc.5` candidates are explicitly recorded as deferred: `@deepseek-ai/dsh-web-deepseek-api` (requires non-optional `@deepseek-ai/dsh-llm-deepseek-account`, whereas this standalone profile uses API-key auth with `@deepseek-ai/dsh-web-search-deepseek` and `@deepseek-ai/dsh-web-fetch-http`), `@deepseek-ai/dsh-agent-team` + `@deepseek-ai/dsh-tool-agent-team`, `@deepseek-ai/dsh-tool-working-directory`, `@deepseek-ai/dsh-tool-executor-ptc` + `@deepseek-ai/dsh-ptc-runtime-node`, spill/pruning/image-offload compaction (`dsh-spill-local`, `dsh-spill-policy`, `dsh-compaction-tool-result-pruner`, `dsh-compaction-image-offload`), and `dsh-repeat-tool-reminder`, `dsh-session-projection-cache`, `dsh-time-context`, `dsh-tool-office`, `dsh-tool-present`, and `dsh-tool-schedule`.
- **Session format and query boundary**: `SESSION_FORMAT_VERSION` remains `4`, `SessionPersistence` still provides no `delete` method, and `SessionQueryEngine.listSessions` still returns one unpaginated list without `updatedAt`. `@deepseek-ai/dsh-session-persistence-jsonl` is namespace-only in `0.2.2-rc.5`.
- **Official compatibility gate**: `config/upstream-baseline.json` moves to `ref: "dsh-v0.2.2-rc.5"` / `packageVersion: "0.2.2-rc.5"`. Upstream publishes the same 12 spec files under `packages/acp/acp/tests`; `codec.spec.ts` remains byte-identical and passes verbatim against `src/codec.ts`, while the 10 `composition` and `internal-api` divergence records were reviewed against `dsh-v0.2.2-rc.5`.

### Runtime and Subagent Lifecycle Adaptation (`src/index.ts`, `src/subagents.ts`, `src/mcp.ts`)

- **Per-step model selection (`agent.model`)**: Upstream removed `ModelSelectionRef` (`install()`, `pinTurn()`, `releaseTurn()`). `installSessionSetup` in `src/index.ts` now calls the single-argument `installModelSelection(agentCtx)` from `@deepseek-ai/dsh-agent`. Model configuration reads `record.agent?.model.current()` (falling back to `fallbackSelection(config)` for unmaterialized probe records) and applies changes via `agent.model.select(...)`, taking effect on the next model step rather than waiting for a new turn.
- **Turn, error, status, and tree quiescence**:
  - Updated `agent/error` listener to `({ agent, error }) => ...` (`turn` removed upstream).
  - Added `agent/status` listener so user cancellation settles cleanly if the agent reaches `idle` without emitting `turn/end`.
  - On `session/event` `turn/start`, updated `inflight.turn = event.data.turn` and reset `inflight.endReason` and `inflight.agentError` so a parent resuming for a follow-up turn after child delivery does not retain stale state; `turn/end` clears `inflight.agentError = undefined` before settlement.
  - Replaced `drainContinuableDescendants` with `subagents.waitForTreeWork(agent)`, `subagents.drainDescendants(parents)`, and `subagents.interrupt(...)`. In `settleAfterQuiescence`, the bridge loops on `agent.whenIdle()` and `subagents.waitForTreeWork(agent)` until the agent is `idle` and `agent.session.seq` is unchanged across the wait; user `session/cancel` invokes non-destructive `subagents.interrupt(childId, { kind: 'ancestor', agent })`, whereas `cancelRecord` during close, `closeRecord`, and `quiesce` invoke `drainDescendants`.
- **Managed subagent activations and parent-card folding**:
  - Removed obsolete `enableRunInBackground` and `toolFilter` options from `tool-subagent` and `tool-subagent-fork` in `config/cordis.yml` (`persona` and `toolFilter` now throw at plugin load). `dsh-tool-subagent` starts a managed activation (`delivery: 'parent'`) and immediately returns `{ kind: 'activation', name }` (`"started subagent <name>"`).
  - `SubagentTracker.start` resolves the initial label from `this.identities.get(info.id)` or `descriptorLabel(child.session)` (`subagent/descriptor`), because `subagent/start` now precedes `subagent/catalog` (v3, carrying `name` and `label`). When `subagent/catalog` arrives after start, `SubagentCard.updateCatalog` updates the linked card or nested descendant entry and emits an update.
  - When the parent's non-error `tool/result` arrives while the direct child is still running (`!card.isFinished`), `SubagentTracker.parentResult` calls `card.recordParentResult(result)` to keep the card `in_progress` and linked while folding live child events. At `subagent/end`, `depth > 1` settles and unlinks immediately, while `depth === 1` calls `settleDeferred()` (or `settle()` when `tool/result` arrives after `subagent/end`) with `[transcriptBlock, ...finalOutput]` and `stop_reason` in `_meta.dsh_subagent`. `SubagentTracker.dispose` keeps child links across `agent/disposed` so trailing `subagent/end` events still finalize the card.
  - Narrowed `isDelegatedSession(header)` in `src/subagents.ts` to `header.origin === 'subagent'` (dropping `parentSession !== undefined`, matching upstream `dsh-acp` so ordinary forks remain listable and restorable).
  - `@deepseek-ai/dsh-user-questions` now enforces `DELEGATED_CALLER` for live agents with `origin === 'subagent'`, complementing the bridge's root-only `approval/request` and `user-questions/request` listeners.
- **MCP config construction**: `mapMcpServers` in `src/mcp.ts` wraps stdio and streamable-http configs in `McpClient.Config({ ..., closeTimeoutMs: 5_000, expandTemplates: false, toolCallTimeoutMs: 60_000, failOnStartupError: true })` while preserving the null-prototype `env` and `headers` records produced by `entriesToRecord`.

## T3 Code Compatibility Fixes

All four T3 Code (`0.1.10`, `driver: "acpRegistry"`) integration fixes are implemented in `src/` and covered by `tests/t3-compat.spec.ts` (in-process and over the built `lib/bin.js` launcher):

1. **Hybrid v2/v1 `initialize` negotiation (`src/index.ts`)**:
   - Registered `parseHybridInitializeRequest` on `methods.agent.initialize` instead of strict SDK schema parsing that rejected v2 `info` and `capabilities` fields alongside v1 `clientInfo` and `clientCapabilities`.
   - Validates that `params` is a non-null, non-array object with integer `protocolVersion` in `[0, 65535]` (rejecting malformed inputs with `-32602`), accepts `protocolVersion >= 1` (such as T3's `2`), and always answers with `protocolVersion: PROTOCOL_VERSION` (`1`).
   - Resolves client capabilities via `params.clientCapabilities ?? params.capabilities` and `clientName` via `params.clientInfo?.name ?? params.info?.name`.

2. **Space-containing executable path stdio MCP bridges (`src/mcp.ts`)**:
   - Passes `command` and `args` directly through `McpClient.Config` to `StdioClientTransport` (`shell: false`), supporting paths with spaces (e.g. `T3 Code App/bin/acp mcp bridge.mjs`).
   - Preserves null-prototype explicit `env` entries (`T3_ACP_MCP_ENDPOINT`, `T3_ACP_MCP_AUTHORIZATION`) over the scrubbed parent environment without mutating `process.env`, uses `toolCallTimeoutMs: 60_000` / `closeTimeoutMs: 5_000` / `expandTemplates: false`, and works cleanly with MCP SDK `2.2.0` auto version negotiation (`server/discover -> -32601` fallback to `initialize`).

3. **Zero-disk-residue ephemeral probe sessions (`src/index.ts`, `src/config-options.ts`, `src/modes.ts`)**:
   - Recognizes probe clients `t3-code-provider-test` and `t3-code-provider-probe` when `mcpConfigs.length === 0`.
   - After validating parameters, MCP declarations, and `assertSessionCredential`, prepares an unmaterialized in-memory `Session` via `ctx.sessions.prepare(sessionId, { meta: { cwd: params.cwd } })` and `makeProbeRecord(...)` without calling `agents.create(...)` (which would trigger `dsh-permission-presets` to append events and flush `.jsonl.zstd` session files to disk).
   - Widened `sessionConfigOptions`, `PermissionPresetDirectory.current`, and `sessionModes` to accept `Agent | Session` so probe `session/new` returns real `configOptions` (via `fallbackSelection(config)`), `modes`, and `available_commands_update`.
   - Closing, cancelling, or disposing an unmaterialized probe session skips disk flush and leaves zero files under `$DSH_ACP_SESSIONS_ROOT`, `$DSH_HOME/acp-sessions`, and `$DSH_AGENTS_HOME`.
   - If `prompt`, `setSessionConfigOption`, or `setSessionMode` is subsequently called on a probe session, `materializeProbeRecord` validates the request first and then lazily materializes and serializes the `Agent` via `agents.create(...)`.

4. **Tightened `imagePromptEnabled` and fail-closed text-only route validation (`src/index.ts`, `src/content.ts`)**:
   - `supportsImageMediaTypes(ctx.get('attachments')?.imageLimits?.mediaTypes)` requires both a mounted attachment store and at least one ACP-supported raster format (`image/png`, `image/jpeg`, `image/webp`, `image/gif`), preventing false `promptCapabilities.image: true` advertisement when an attachment store omits raster MIME types.
   - `admitPrompt` calls `assertImageRoute` before `attachments.saveImages`, rejecting prompts containing images on text-only models (such as `deepseek-v4-pro`) with `-32602` (`model "<id>" does not declare image input`) before any image bytes are persisted or queued.
